지원 문의

경과 기간 #

일반적인 기간은 근무 시간 기준으로 측정됩니다. 월요일부터 금요일까지 하루 8시간 근무하는 달력에서 3일짜리 작업은 24근무시간이 걸리며, 목요일에 시작하면 월요일에 끝납니다. 주말은 계산에 포함되지 않습니다.

경과 기간은 실제 시계 시간 기준으로 측정됩니다. 주말, 휴일, 달력의 모든 비근무 예외를 포함하여 하루 24시간, 주 7일 연속으로 계산됩니다.

팀의 근무 여부와 무관한 모든 것에 사용하십시오. 콘크리트 양생, 페인트 건조, 테스트 소크, 규제상의 대기 기간, 운송 중인 배송 등이 해당됩니다.

경과 기간 입력 #

단위 앞에 e를 붙여 기간을 입력합니다:

입력 결과
3d 3근무일
3ed 3경과일 — 시계 시간으로 72시간
2ew 2경과주 — 달력 기준 14일
8eh 8경과시간

단위는 min, h, d, w, m(분, 시간, 일, 주, 월)이며 모두 e를 붙일 수 있습니다. 약어는 번역되므로 영어가 아닌 인터페이스에서는 해당 언어의 단위 문자를 사용하되, e 표시는 그대로 유지됩니다.

직접 입력하는 대신 작업 속성 대화 상자의 기간 편집기에 있는 Elapsed 체크박스를 사용할 수도 있습니다. 툴팁이 곧 정의입니다:

경과. 체크하면 기간이 달력에 정의된 근무 시간 동안만이 아니라 연속으로(24/7) 계산됩니다.

체크박스를 체크하거나 해제하면 보이는 숫자는 그대로 유지되고 그 의미만 바뀝니다. 즉 3d가 3ed가 됩니다. 3근무일을 같은 길이의 경과일 수로 조용히 변환하지 않습니다.

경과 단위의 값 #

경과 단위는 프로젝트 달력을 무시하고 고정된 달력 산술을 사용합니다:

단위 경과 값
1경과일 24시간
1경과주 7일 = 168시간
1경과월 30일 = 720시간

이를 프로젝트 속성에서 정해지는 근무 단위(기본값: 하루 8시간, 주 5일, 월 20일)와 비교해 보십시오. 따라서 1w는 40근무시간이지만 1ew는 시계 시간으로 168시간입니다.

종속성의 경과 지연 #

같은 개념이 종속성의 지연에도 적용되며, 바로 여기에서 가장 중요합니다. "이 작업이 끝나고 3일 후에 다음 작업을 시작"한다는 말은 보통 3근무일이 아니라 달력 기준 3일을 뜻합니다. 그렇지 않으면 금요일 완료가 후속 작업을 수요일로 밀어냅니다.

Task Properties의 Predecessors 탭에서 각 링크에는 지연 옆에 같은 의미의 Elapsed 체크박스가 따로 있습니다:

체크하면 지연 시간이 달력에 정의된 근무 시간 동안만이 아니라 연속으로(24/7) 계산됩니다.

직접 입력할 수도 있습니다. 3ed의 지연은 달력 기준 3일입니다.

가져오기 및 내보내기 #

경과 기간과 지연은 Microsoft Project 형식의 일부이며 양방향 왕복 과정에서 유지됩니다. Microsoft Project에서 가져온 3ed 기간은 3ed로 유지되며 경과 기간으로 다시 내보내집니다.
