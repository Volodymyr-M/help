# 経過期間

通常の期間は**稼働時間**で測定されます。月曜から金曜、1日8時間のカレンダーでは、3日間のタスクは24稼働時間かかり、木曜日に開始すると月曜日に終了します。週末はカウントされません。

**経過**期間は**暦上の時間**で測定されます。週末、祝日、および[カレンダー](/ja/setting-up-project/calendars/index.md)上のすべての非稼働例外を通して、1日24時間、週7日、連続してカウントされます。

コンクリートの養生、塗料の乾燥、ソークテスト、規制上の待機期間、輸送中の配送など、チームが稼働しているかどうかに関係なく進むものに使用します。

## 経過期間の入力

単位の前に<strong>`e`</strong>を付けて期間を入力します：

| 入力 | 結果 |
|----------|---------|
| `3d` | 3稼働日 |
| `3ed` | 3経過日 — 暦上の72時間 |
| `2ew` | 2経過週 — 14暦日 |
| `8eh` | 8経過時間 |

単位は`min`、`h`、`d`、`w`、`m`（分、時間、日、週、月）で、いずれにも`e`を付けることができます。略語は翻訳されているため、英語以外のインターフェースではその言語の単位文字を使用してください。`e`マーカーはそのままです。

入力する代わりに、[タスクのプロパティ](/ja/building-schedule/task-properties/index.md)ダイアログの期間エディターにある**経過**チェックボックスを使用することもできます。そのツールチップがそのまま定義になっています：

> Elapsed（経過）。チェックすると、期間はカレンダーで定義された稼働時間中だけでなく、連続して（24時間365日）カウントされます。

チェックボックスをオンまたはオフにしても、表示されている数値はそのままで、その意味だけが変わります：`3d`は`3ed`になります。3稼働日を同等の経過日数に黙って換算することはありません。

## 経過単位の値

経過単位はプロジェクトカレンダーを無視し、固定の暦計算を使用します：

| 単位 | 経過値 |
|------|---------------|
| 1経過日 | 24時間 |
| 1経過週 | 7日 = 168時間 |
| 1経過月 | 30日 = 720時間 |

これを稼働単位と比較してみましょう。稼働単位は[プロジェクトのプロパティ](/ja/setting-up-project/project/index.md)で決まり、デフォルトでは1日8時間、1週間5日、1か月20日です。したがって、`1w`は40稼働時間ですが、`1ew`は暦上の168時間です。

## 依存関係の経過ラグ

同じ考え方は[依存関係](/ja/building-schedule/dependencies/index.md)のラグにも当てはまり、ここが最も重要なところです。「このタスクの終了の3日後に次のタスクを開始する」は、通常3稼働日ではなく3*暦日*を意味します。そうでなければ、金曜日の終了は後続タスクを水曜日まで押しやってしまいます。

タスクのプロパティの**先行タスク**タブでは、各リンクのラグの隣に独自の**経過**チェックボックスがあり、意味は同じです：

> チェックすると、ラグはカレンダーで定義された稼働時間中だけでなく、連続して（24時間365日）カウントされます。

直接入力することもできます：`3ed`のラグは3暦日です。

## インポートとエクスポート

経過期間と経過ラグはMicrosoft Project形式の一部であり、双方向のラウンドトリップでも保持されます。Microsoft Projectからインポートした`3ed`の期間は`3ed`のままで、経過期間としてエクスポートし直されます。
