サポートに問い合わせ

WBSコード #

すべてのタスクにはWBSコードがあります。これはアウトライン内でのタスクの所在を示すものです。初期状態では、1、1.1、1.2、1.2.1のような単純なアウトライン番号です。タスクテーブルでWBS列をオンにすると表示されます。

WBSコードマスクは、これらのアウトライン番号を独自に設計した構造化コードに置き換えます。これにより、タスクは1.1.1ではなくPROJ-A-01や1.A.001のように表示されます。契約、コストコード体系、顧客の報告形式など、番号付けの標準を持つ組織は、Inganttのコードをその標準に合わせるためにこれを使用します。

設定するには、Project → WBS Code Definitionを開きます。

WBSコードとアウトラインコードの違い #

  • WBSコードは構造的なものです。タスクごとに1つだけ存在し、アウトライン内でのタスクの位置から導出されます。タスクを移動すると自動的に番号が振り直されます。
  • アウトラインコードはタグです。部門、フェーズ、コストセンターなどのルックアップリストを定義し、階層とは無関係にタスクに値を割り当てます。1つのタスクは、複数のアウトラインコードから複数の値を持つことができます。

マスクの定義 #

ダイアログは3つの部分で構成されています。

プロジェクトコードのプレフィックス #

プロジェクト内のすべてのコードの先頭に付く固定テキストです。プレフィックスをPROJにすると、区切り文字に応じてPROJ.1.1やPROJ-A-01のようなコードになります。プレフィックスを付けない場合は空のままにします。

コードマスク #

アウトラインレベルごとに1行で、Add Levelで追加します。各行では以下を設定します：

フィールド 機能
Level この行が適用されるアウトラインの深さ。レベル1は最上位のタスク、レベル2はその子タスク、というように続きます。
Sequence このレベルで使用する文字：Numbers（1、2、3）、Uppercase Letters（A、B、C … Z、AA）、Lowercase Letters（a、b、c … z、aa）、またはCharacters。
Length このレベルの最大文字数。空のままにするとAnyと表示され、制限なしになります。
Separator このレベルと次のレベルの間の文字（.や-など）。

フィールドの動作について知っておくべき点が2つあります：

  • Lengthは数字の先頭をゼロで埋めます。 Numbersレベルで長さを3にすると、9番目のタスクは009になります。文字のレベルは埋められません。
  • Charactersは、Inganttが生成するコードではNumbersと同じように動作します。これはMicrosoft Projectとの互換性のために存在するもので、Microsoft Projectでは自分で入力するレベルを意味します。

すべてのレベルを定義する必要はありません。マスクの最後の行より深いレベルは、.区切りの数字にフォールバックするため、5階層の計画に3行のマスクを適用しても完全なコードが生成されます。

オプション #

Generate WBS code for new taskとVerify uniqueness of new WBS codesはプロジェクトとともに保存され、Microsoft Projectとのラウンドトリップでも保持されます。Inganttでは、少なくとも1つのレベルを持つマスクはすべてのタスクに自動的に適用され、コードはアウトラインに従うため構造上一意になります。

マスクを保存すると何が起こるか #

Inganttはプロジェクト全体の番号をすぐに振り直します。コードは、タスクの追加、削除、インデント、アウトデント、移動など、構造が変わるたびにアウトラインから再構築されるため、常にタスクの現在の位置を表します。

はっきり言っておくべきことがあります：WBSコードはタスクの永続的な識別子ではありません。 タスクを移動すると、そのコードは変わります。タスクに付いて回るラベルが必要な場合は、代わりにアウトラインコードまたはカスタムテキストフィールドを使用してください。

インポートとエクスポート #

マスクはMicrosoft Project形式の一部であり、ラウンドトリップでも保持されます。マスク付きでインポートされたプロジェクトはマスクを保持したままエクスポートされ、そのタスクコードはMicrosoft Projectが生成したものと一致します。
